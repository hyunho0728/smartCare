# 상태 변화 알림 실행

기존 시스템 점수의 안전·주의·경고·위험 등급이 악화될 때 담당 복지사에게 웹 알림을 저장합니다. Gemini를 호출하지 않습니다. 첫 검사와 담당 변경 후 첫 검사는 기준만 저장하며, 과거 알림을 소급 생성하지 않습니다.

## 로컬 실행

기존처럼 `python app/app.py`로 실행하면 개발 서버의 실제 reloader 자식 프로세스에서 검사 스레드가 시작됩니다. 시작 즉시 검사하고 5분마다 반복합니다. `STATUS_ALERT_AUTO_START=0`으로 자동 시작을 끌 수 있습니다. 테스트 앱에서는 자동 실행하지 않습니다.

## 운영 실행

웹 서버와 별개로 아래 명령을 프로젝트 루트에서 실행하고 프로세스 관리 도구로 재시작하도록 설정합니다. 기존 `.env`의 동일한 DB 설정을 사용합니다. 웹 서버를 WSGI로 실행할 때는 자동 검사 스레드가 시작되지 않습니다.

```powershell
$env:PYTHONPATH = 'app'
.venv\Scripts\python.exe -m flask --app app/app.py status-alert-worker
```

동일 DB의 검사 작업자는 하나를 운영하는 것을 권장합니다. 중복 실행 시에도 대상자 행 잠금·상태 버전·알림 고유 키로 중복 알림을 방지합니다. 중단은 Ctrl+C로 합니다.

`STATUS_ALERT_STATE`, `STATUS_ALERT` 테이블은 기존 `db.create_all()`로 생성합니다. 기존 테이블 변경과 기존 알림 삭제는 없습니다. 운영 DB 계정에 테이블 생성 권한이 필요합니다.

## 확인과 한계

- 관리자 알림 영역에 마지막 조회 시각과 정기 검사 성공 시각을 표시합니다. 일부 대상자 검사나 완료 시각 저장이 실패하면 이전 성공 시각을 유지하고 서버 로그에 오류를 남깁니다.
- 건강 입력 후에도 검사하며, 알림 저장 실패는 이미 저장된 건강 기록을 취소하지 않습니다. 다음 정기 검사에서 재시도합니다.
- 서버가 중지된 동안은 감지하지 못합니다. 재시작 후 마지막 기준과 현재 상태를 비교하므로 중간의 악화·회복을 복원하지 못할 수 있습니다.
- 알림 시각은 감지 시각입니다. 정확한 악화 발생 시각이나 새 질환 진단을 뜻하지 않습니다.
- 점수 계산에는 기존 전체 이력을 사용하고, 알림 근거 열람에는 당시 건강·접속 기록을 각각 최근 30개까지 보존합니다. 자유 메모와 검진표 원문은 복사하지 않습니다.
- 알림 열람과 읽음 처리는 별개입니다. 담당 변경 시 기존 알림은 보존하지만 이전 담당자와 새 담당자 모두 이전 담당자에게 발송된 알림에 접근할 수 없습니다.
