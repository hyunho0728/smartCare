# 통합 로그인 및 8순위 UI 개선 기록

## 동작

- PC·모바일 첫 접속 `/` → `/login`. 유효한 세션이 있으면 `/user` 또는 `/admin`으로 이동합니다.
- 통합 화면의 ‘사회복지사로 로그인’ 체크박스는 기본 해제입니다. 어르신은 기존 전화번호, 사회복지사는 기존 아이디·비밀번호를 사용합니다.
- 체크박스를 바꾸면 입력값·오류가 초기화됩니다. 요청 중에는 역할 선택·입력·로그인·등록 링크가 잠깁니다.
- `/user`와 `/admin`은 역할을 검사합니다. 다른 역할로 로그인된 경우 자신의 화면으로 이동합니다. 로그인 실패 시 기존 세션은 유지됩니다.
- 한 브라우저 세션은 한 역할만 유지합니다. 이전 두 역할 정보가 함께 남은 세션은 재로그인이 필요합니다. 기존 단일 역할 세션은 호환됩니다.
- 공개 등록 화면은 `/register/user`, `/register/worker`입니다. 기존 등록/가입 API와 입력 흐름을 재사용합니다.
- 로그아웃·세션 만료는 통합 로그인으로 돌아갑니다. 역할 전환은 로그아웃 후 다시 로그인합니다. 어르신 원격 로그아웃을 유지했습니다.
- PC의 어르신 화면은 최대 480px 중앙 배치입니다. 건강 입력·파일 선택·등록은 PC에서도 사용 가능합니다. 카메라 촬영은 기기와 브라우저 지원에 따라 파일 선택으로 표시될 수 있습니다.

## 반응형·AI

- 768px 이하 관리자 화면은 서랍형 메뉴, KPI 2열, 어르신 카드 목록과 상세 한 열 배치를 사용합니다.
- 메뉴 선택·바깥 영역·Escape로 메뉴를 닫습니다. 메뉴 포커스 순환과 선택 후 제목 포커스 이동을 처리합니다.
- 기존 알림과 보조 표는 영역 내부 가로 스크롤, 모달·가입 폼은 화면 크기 안에서 스크롤합니다. 주요 모바일 버튼은 최소 44px입니다.
- 생활패턴/검진표 분석은 스피너·상태 문구를 표시하며 실제 API 진행률이 없어 퍼센트는 표시하지 않습니다.
- 생활패턴은 어르신별, 검진표는 문서별 상태를 유지합니다. 목록 재렌더·탭 이동·팝업 재열기에서 중복 요청을 막고 실패 시 기존 결과를 보존합니다.
- 기존 생활패턴 서비스가 API 오류를 성공한 분석 문자열로 반환하던 부분도 수정했습니다. 키 누락·할당량·빈 응답·요청 오류를 실패로 반환하므로 실패 메시지가 기존 성공 결과를 덮어쓰지 않습니다.

## 검증

전체 자동 테스트 34개가 통과했습니다. 렌더링된 템플릿과 외부 JavaScript의 문법 검사 10개, `git diff --check`도 통과했습니다. 화면 캡처는 `tests/ui_artifacts/`에 보관했습니다.

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

운영 MySQL과 실제 Gemini를 호출하지 않습니다. 인증/검진표 API는 가상 SQLite, AI는 모의 응답으로 검증합니다. 브라우저 테스트에는 개발 도구 `playwright`와 기존 Windows Chrome이 필요합니다. 브라우저 없는 환경에서는 `test_auth.py`와 `test_checkup.py`를 각각 실행할 수 있습니다.

검사 항목: 역할 전환·입력 초기화·로그인 실패/중복 요청·DB 저장 실패·세션 호환/만료·직접 URL 접근·원격 로그아웃·등록/가입·PC 어르신 화면·모바일 사회복지사 로그인·360/390/768/1280/1440px 화면·메뉴·모달·알림·느린 AI·재렌더 중 중복 분석 방지·실패 시 기존 결과 유지·기존 검진표 추출/확정 저장.

실제 휴대폰에서 촬영 입력, 키보드가 열린 로그인/등록 폼, 모바일 PDF 뷰어 동작을 추가 확인해야 합니다. 실제 서비스와 연동하는 운영 MySQL 환경은 이번 테스트 범위 밖입니다.

추천 커밋 메시지: `기능추가: 역할 선택 통합 로그인과 PC·모바일 화면 개선`
