# 건강 종합 분석 구현 기록

## 사용 방법

담당 사회복지사로 로그인해 ‘건강 분석 리포트’ 또는 어르신 상세의 ‘AI 건강 종합 분석’을 실행합니다. 검진 자료는 기존 원본 대조·수정·확정 절차를 완료한 결과만 사용합니다. 새로고침과 재로그인 시 DB의 최신 결과를 복원하며, 최근 20개 이력에서 이전 결과를 선택할 수 있습니다.

생활·접속 자료는 분석 시작 시점의 최근 30일입니다. 최근 7일과 이전 23일을 구분합니다. 확정 검진은 검진일 기준 최신 2개를 선택하고, 날짜 미상은 업로드일로 정렬합니다. 검진일 미상·1년 이상 지난 기록·판독 불가·미지원 항목·상충 값은 한계로 표시합니다. 자료가 전혀 없으면 422를 반환합니다.

질환 자동 등록이나 기존 위험점수 변경은 하지 않습니다. 점수와 기존 생활패턴 요약은 시스템 지표로 표시하고, 종합 AI 결과와 구분합니다. 10명 테스트 데이터 제작은 포함하지 않았습니다.

## API와 저장

- `POST /api/admin/elders/<user_id>/life-pattern-ai`: 기존 `success`, `analysis`를 유지하고 `analysis_id`, `analyzed_at`, `model`, `result`, `input_snapshot`을 추가합니다.
- `GET /api/admin/elders/<user_id>/health-analysis`: `latest`, `selected`, 최근 20개의 `history`를 반환합니다. 결과가 없으면 latest/selected는 null입니다. `?analysis_id=<id>`로 과거 결과를 선택합니다.
- `result`: `summary`, `findings[{title, detail, source_refs}]`, `recommended_actions`, `limitations`입니다. 없는 source ref나 잘못된 JSON은 실패로 처리합니다.
- `input_snapshot`: 생활 기록 범위, 선택 문서 ID·확정 버전·검진일, 분석에 사용한 정규화 자료와 근거 참조입니다. 원본의 직접 식별 정보나 자유 메모는 저장하지 않습니다.
- 새 테이블은 기존 `db.create_all()` 초기화에 포함됩니다. 기존 인증·검진 테이블의 컬럼은 변경하지 않습니다. 실행자와 성공 시각을 보존하며 재분석은 별도 행을 추가합니다.
- 유효한 사회복지사 세션과 현재 담당자 일치가 필요합니다. 미배정 대상자도 차단합니다. 분석 대기 중 담당자 변경은 저장 직전에 다시 검사합니다.
- 오류 시 DB를 rollback하고 기존 성공 결과를 보존합니다. 401 인증, 403 담당자 불일치, 404 대상/이력 없음, 422 분석 자료 없음, 429 할당량, 503 키 누락, 502 외부 요청/응답 검증 실패, 500 저장/예상 밖 오류를 반환합니다.

## 개인정보와 한계

외부 요청은 검사명·수치·단위·참고범위와 등록 질환의 허용 목록으로 구성합니다. 이름·전화번호·주소·기관명·검진 원문·자유 메모·로그인 IP/브라우저 정보는 전달하지 않습니다. 혈당·혈압 단어만으로 질환을 추정하지 않습니다. 정규화하지 못한 항목·값·질환은 제외하고 한계를 표시합니다.

검진 단위와 참고범위는 허용된 표현만 전달하므로 복잡한 서술형 참고범위가 제외될 수 있습니다. 이 경우 원본 확인이 필요합니다. 분석 근거 버튼은 해당 문서의 현재 검진 확인 화면을 엽니다. 과거 분석 당시 값은 분석 스냅샷에 보존되므로, 재확정된 현재 문서와 다를 수 있습니다.

Gemini에 진단·처방·치료 변경 및 새 위험등급 생성을 금지하도록 요청합니다. JSON 형식·근거 참조 검증은 사실성이나 의학적 정확도를 보장하는 평가가 아닙니다. 실제 응답 품질은 별도 확인해야 합니다.

## 검증 방법과 운영 확인

전체 자동 테스트 48개가 통과했습니다. 종합 분석 서비스/API 13개, 인증 API 10개, 실제 Chrome 인증·종합 분석 브라우저 4개, 기존 검진 서비스/API 20개와 검진 브라우저 1개를 포함합니다. PC·모바일 360/390/768/1280/1440px에서 화면 넘침을 검사했습니다. Python 구문 검사와 JavaScript 문법 검사 10개도 통과했습니다.

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

API 테스트는 격리된 SQLite, 외부 AI는 모의 응답을 사용합니다. 브라우저는 기존 Windows Chrome과 Playwright로 실제 템플릿/API를 검사합니다. 운영 DB와 실제 Gemini 호출은 수행하지 않았습니다.

운영 적용 시 서버를 재시작해 신규 테이블 생성 권한과 생성 결과를 확인해야 합니다. 실제 Gemini에서 JSON 계약·지원 모델·60초 제한과 실제 검진 자료의 정규화 범위를 확인하고, 실제 휴대폰의 긴 결과 스크롤·검진 PDF 열람을 추가 확인해야 합니다. 기존 검진표 확정 저장과 인증 흐름은 회귀 테스트 대상입니다.

## 4·5순위: 상태 근거와 관측값 비교

기존 안전·주의·경고·위험 4단계와 점수 계산을 유지합니다. 점수는 높을수록 안전합니다. 신규 분석은 시작 시점의 시스템 점수·감점 항목을 저장하고, 직전 성공 분석 당시 점수·감점 변화와 비교합니다. 점수는 0~100으로 보정되므로 감점 변화 합계와 실제 점수 차이가 다를 수 있습니다. 검진 수치는 점수를 변경하지 않습니다.

### 입력과 결과 계약

- `input_snapshot.version=2`, `system_status`, `comparisons`, `previous_analysis_id`를 기존 JSON 컬럼에 저장합니다. 새 DB 컬럼이나 마이그레이션은 없습니다.
- `system_status`에는 점수, 등급, 표시명, 계산 기준 시각과 자유 메모를 제거한 감점 항목이 있습니다. 기존 계산 서비스에 선택적 `now` 인자만 추가해 같은 기준 시각을 사용합니다.
- `comparisons.life`는 최근 7일/이전 23일의 날짜별 마지막 생활 기록, 건강 척도·혈압·혈당 평균과 표본 수, 결식 비율, 접속한 날짜 수·관측 가능한 날짜 대비 비율, 미기록 날짜를 포함합니다. 예정 식사는 분모에서 제외합니다. 최근 구간은 시작 시각 포함, 이전 구간은 끝 시각 제외입니다. 부분 날짜도 관측 범위와 겹치면 날짜 분모에 포함하므로 7일 시간 범위가 달력 날짜 8개와 겹칠 수 있습니다.
- `comparisons.checkups`는 두 확정 문서의 동일 항목·동일 단위 비교입니다. 정확한 숫자만 차이를 계산하고 단위 환산은 하지 않습니다. 무단위 시력은 좌우 각각 비교합니다. 날짜 미상·동일 날짜·미래 날짜·상충·단위 불일치·부등호·문자 값은 원래 값과 비교 불가 이유를 표시합니다.
- `comparisons.previous_analysis`는 시작 시점에 선택한 직전 성공 분석 ID와 입력 동일 여부, 새 생활 기록 수, 검진 문서/확정 버전 변경, 정규화된 등록 질환 변경, 가능한 경우 시스템 점수·감점 변화를 저장합니다. 과거 AI 문구는 비교 입력에 사용하지 않습니다.
- `result.priority_actions`는 `action`, `reason`, `source_refs`, `priority`입니다. 행동은 연락 확인/생활·측정 기록 확인/검진 원본 확인/기존 의료 상담 여부 확인으로 제한하고 확인 순서는 우선 확인/일반 확인입니다. 존재하지 않는 근거와 빈 이유는 실패 처리합니다. 기존 요약·확인 사항·권장 확인·한계 필드는 유지합니다.
- POST/GET 응답의 `current_status`는 현재 조회 시점의 별도 시스템 계산값이며, 저장된 결과를 다시 계산하거나 덮어쓰지 않습니다. 결과의 `needs_reanalysis`는 현재 입력과의 차이를 나타냅니다. 현재 점수의 조회 계산만 실패한 경우 GET은 저장 결과와 `current_status_error`를 반환하고 임의 점수는 만들지 않습니다. 신규 분석의 점수 계산 실패는 저장·외부 호출 전에 오류로 반환합니다.

### 화면과 호환

분석 당시 상태 → 우선 확인 → 변화 비교 → 요약·근거 → 한계 순서로 표시합니다. 현재 목록 상태와 현재 조회 상태에는 각각 기준 시각을 표시합니다. 관측값 증감을 호전·악화로 단정하지 않으며, 같은 자료의 재분석을 새 건강 변화로 표시하지 않습니다. 근거에서 현재 검진 확인창을 열 수 있고 재확정된 현재 값과 분석 당시 값이 다를 수 있다는 안내를 제공합니다.

이전 형식의 결과는 그대로 열람하고 비교/상태 정보 미저장 안내를 표시합니다. 로딩·중복 요청 방지와 실패 시 기존 결과 보존은 유지합니다. 조회 갱신 버튼으로 현재 자료와 다시 대조할 수 있습니다. 그림·PDF 테스트 산출물은 로컬에만 보관하고 Git에서 제외합니다.

## Gemini JSON 검증 오류 보완

Gemini에 보내는 수동 스키마와 로컬 Pydantic 계약에서 배열 수·문자 길이 안내가 달랐습니다. 생성 스키마를 로컬 계약에서 만들고 길이 제한과 핵심 근거 선택을 설명으로 전달하도록 수정했습니다. 제한을 벗어난 JSON, 빈 근거, 허용되지 않은 행동, 잘못된 참조는 계속 거절합니다.

실제 API에서 간단한 배열의 minItems/maxItems는 동작했지만 이 전체 중첩 계약에 적용하면 response_schema/response_json_schema 모두 400 INVALID_ARGUMENT를 반환했습니다. 따라서 중첩 계약은 단순한 스키마와 길이 설명을 사용하며, 수신 후 로컬 검증은 유지합니다. [Google 구조화 출력의 제한 안내](https://ai.google.dev/gemini-api/docs/generate-content/structured-output?hl=en)에 따라 복잡한 제약을 다시 추가할 때는 실제 API 확인이 필요합니다.

- `app/services/health_analysis_service.py`: 계약에서 스키마·길이 안내 생성, 오류 항목별 안내, 응답 값과 임의 필드 이름을 제외한 안전한 검증 로그, MAX_TOKENS 출력 중단 안내.
- `app/services/health_comparison_service.py`: 기존 계산의 ‘앱 미접속 경과’ 항목을 정규화해 분석 시작 실패 방지. 점수 계산은 변경하지 않습니다.
